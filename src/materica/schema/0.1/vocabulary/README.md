# Vocabulary

The tokens of schema 0.1, as the specification's tables give them (layer L1). Every file here is generated by
`scripts/gen_vocabulary.py`, and CI fails when one differs from its table; edit the table, never the file. Each
file states its `$id`, its path under `https://w3id.org/materica/schema/0.1/`, names its table in its
`$comment`, and holds tokens only: a rule a table states in prose is code with its own cases.

| File | Table | Holds |
|---|---|---|
| `reasons.json` | `read_side_contract.md` section 4 | each reason code and the status it gives; the codes again as an enumeration in `$defs`, which `read_result.json` refers to |
| `fields.json` | `record_format.md` section 4.1 | each field's unit, forms, required conditions and label |
| `conditions.json` | `provenance.md` section 6.1 | each condition, numeric with its unit or token with its tokens |
| `specimen_facts.json` | `provenance.md` section 6.2 | each specimen fact, and the tokens of its `token` member; its members are structure, the writer schema's |
| `acceptances.json` | `declarations.md` section 4.1 | the acceptance kinds |

`core/vocabulary.py` reads them when it is first imported; a file of another shape is a broken installation,
and loading it raises.

# Specification sync

Checks that what is written in two places says the same in both. The specification is normative, so where a
check here fails, the specification holds and the other copy is wrong; for a released schema, the manifest
holds.

| Test | Holds together |
|---|---|
| `test_schemas.py` | the specification's member tables (the envelope, the read request and result) and the schemas' members; the token lists written in the schemas by hand (sections, record types, `want`s, suites, overlay purposes, status-object tokens, read statuses, case operations) and the specification's tables or text, with a control that changes the text; and every schema file's `$id` against its path, with a control |
| `test_value_fields.py` | the value-field part of the writer schema and the specification: the member tables of a value field (each form's), the provenance object, the statistics block and its uncertainties, the conditions and the specimen facts; the members that may hold a status object, with their tokens, and none other (`provenance.md` section 1 item 5); the specification's examples of these shapes, which must be valid; the members marked `x-materica-write-only`, exactly those step 8 does not check; every `const` a token the schema or vocabulary lists; each token condition and specimen fact bound to its row's list, a fact's identifier to the pattern of the form its row writes, and a member a row gives as present exactly with some tokens (a disease or treatment state's `text`) so in the writer, and each rule across objects (`provenance.md` sections 2, 3 and 7) refusing a field without its member; the vocabulary's bindings, each applied by the one writer definition named for it and holding what the vocabulary's rows give (each section's field names, the replaced fields, each field's forms, bases, unit and label, each numeric condition's unit), and a row added to a copy of the text taken by the unchanged writer; and the writer's description naming, in code spans, exactly the members that leave it open, a map a binding closes being closed. Its controls change a table, a status row, a quote, the description, the schema or a binding |
| `test_name_overlaps.py` | the names valid at one place, kept more than one slip apart (`record_format.md` section 10), a namespace being one object's members with those its `allOf` refers to, and one meaning per name, over the schemas, the vocabulary (less its bindings, which declare no member), and the specification's JSON examples, member and token tables and name-keyed sentences; `name_overlaps.py` collects the names and gives the flags, and `name_overlaps.json` allows each one judged intended, with its reason and a safeguard quote that must stay in its document. Its controls seed a `material_form` reused, `lots` beside `lot`, `fillin` beside `fill_in`, `origins` beside `origin`, and `forms` beside `form` and `bases` beside `basis` across an `allOf`, each in one input, and break the allowlist: a safeguard gone, an entry stale, a seventh meaning of `basis`, an entry with no safeguard and no reason |
| `test_reason_steps.py` | the reason table's `Step` column (`read_side_contract.md` section 4, generated into `vocabulary/reasons.json`) and the text: each code named at each step the table gives it, in the step's item in section 3 or a passage the item hands its checks to (step 6 giving an overlay the codes of steps 1 to 5, which the table must give at step 6 too), no step's item or handed passage naming a code the table does not give it there but for listed mentions, and each code no step gives named in its procedure's document; and the code of steps 0 to 5, statically (each `Reason`, by any name ending in `Reason`, constructed in a function placed at a step that gives its code, in every module of the core) and traced through every read case file under each claim it agrees with, every pair of code and step the table allows there reached. Its controls change the table (step 6 dropped from each code of steps 1 to 5), a step's text and a handed passage, the code (a reason built through the module, by keyword, with its code not written out, in a module no list names) and a step-0 function |
| `test_released_schemas.py` | each released schema version's directory and its entry in `released_schemas.json`, which `scripts/freeze_schema.py` writes at release: no file added, removed or changed, every `$id` still its path, and no version listed without its directory. Its controls run on a copy of the tree with 0.1 frozen: a file changed, added or removed, the directory gone, and an `$id` frozen wrong |
| `test_envelope.py` | `core/envelope.py` and the generated reader schema, which accept and refuse the same conformance inputs |
| `test_cases_md.py` | each suite's `CASES.md` and its case files: one row per file, the expected column as the file states it, and each heading the specification's row for its case |
| `test_case_steps.py` | `case_steps.json` and the case files: every case file mapped to the implementation step whose code first runs it (S2 by its pieces, `S2a-1` to `S2b-2`, or a list of pieces whose order is not fixed), and every case file of a step done passing; the runner reports the others as not yet runnable |
| `test_references.py` | each reference in the specification, the architecture draft and the documentation plan, in the forms its docstring lists, and the section, item or title it names; each case tag and a row of a Cases table, and each row and a tag; and the items of each numbered list, no two with one number. References that are right but that the forms read wrongly are allowed by name, each with its reason |

The vocabulary and the generated schemas and shapes are checked by their generators' `--check`, which CI runs
(`scripts/README.md`). `schemas.py` gives jsonschema validators for the package's schemas, each reference
resolved to a file in this tree, never over a network.

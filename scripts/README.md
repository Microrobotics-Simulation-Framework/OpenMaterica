# Scripts

Development and CI tools; nothing in the package imports them. All but `gen_shapes.py` use Python's standard
library only, so the sign-off check runs before any dependency is installed.

| Script | What it does | When CI runs it |
|---|---|---|
| `check_confidential.py [--key-file KEY] [--messages RANGE \| --pre-push REMOTE] [--ref-name NAME]` | checks that no tracked file, and no message of a commit in `RANGE`, names one of the maintainer's private projects or carries a private path (CONTRIBUTING, "Confidentiality"); the names by their HMAC-SHA256 in `confidential_digests.txt`, under a key from `CONFIDENTIAL_SCAN_KEY` or `--key-file`, and the paths without a key. A finding gives a term's first letter and length, never the term. A binary file, or text in UTF-16 or UTF-32, is read by its printable runs of four ASCII characters or more; what a file holds compressed is not read. `--pre-push`, from git's pre-push input on standard input, checks what a push to `REMOTE` publishes instead: the name of each ref it writes, each file content and annotated tag the remote lacks by what it advertises now (`git ls-remote`), at each path it has, and each commit's message. `--ref-name` checks a ref's name too. `--digest` writes the digest file from terms on standard input | on every pull request and push, in the first job, whatever the change touches, with the messages the event brings and a pull request's branch name; without the secret, the paths only, with a warning |
| `pre-push` | git's pre-push hook, not run by CI: `check_confidential.py --pre-push` with the push's remote and refs, and `--key-file` from `git config openmaterica.scanKeyFile` where set (`~` expanded), or `CONFIDENTIAL_SCAN_KEY`; refuses the push on a finding, and without a key unless `git config openmaterica.scanWithoutKey true` says the clone has none (the paths alone). Installed by hand (CONTRIBUTING, "Confidentiality") | never: CI's own scan runs in the first job |
| `check_signoff.py <base> <head>` | checks that every commit in `base..head` carries a DCO `Signed-off-by` from its author (CONTRIBUTING constraint 1); the design commits made before the first code commit are exempt, by ancestry of one pinned commit | on every pull request, in the first job, whatever the change touches |
| `check_site.py <staged site> [--readme README.md]` | checks a copy of the site as the Pages workflow stages it: it holds no symbolic link and no hidden path, which the Pages artifact would publish dereferenced or leave out; in every page (`*.html`, `*.htm`, `*.xhtml`), each local link, image and icon, and each icon of the web manifest, resolves to a file of the copy (a directory to its `index.html`, a fragment to an anchor); each page has one content security policy in its head as a browser reads it, before anything it loads or any style, that gives no directive twice, whose default is `'none'` and whose sources are on a closed list (`'none'`, `'self'`, `'unsafe-inline'`, hashes, nonces, `data:`); nothing loads from elsewhere (an image, an icon, a script, a style, a frame, an SVG image or use, a `background`, a style's `url()` or `@import`, in the page or a stylesheet of the copy it loads, whose local addresses resolve too); no page has a `<base>`; and each image of the README, inline, as HTML or by a reference, by a path or a URL into this repository, names a file of the tree. Standard library only | in the site job, on the copy its staging step writes, on every change but one to documentation alone |
| `check_wheel.py <wheel>` | checks that the built wheel holds `py.typed`, every file under `data/` and `schema/` byte for byte and no other there, the licence as an SPDX expression with its file (PEP 639), no run-time dependency, and nothing outside the package | in the static job, after `uv build`, when a change touches code |
| `freeze_schema.py <MAJOR.MINOR> \| --check` | at a release, adds the schema version to `tests/spec_sync/released_schemas.json`, with every file under `src/materica/schema/<version>/` and the SHA-256 of its bytes; refuses a version whose `$id`s are not their paths, and never rewrites one already there. `--check` writes nothing and fails where a released version's file was added, removed or changed, an `$id` is not its path, or its directory is gone (CONTRIBUTING, "Release gate"); it refuses a `-dev` directory, which the release renames first (`src/materica/schema/README.md`, "The next line") | not as a step of its own: `tests/spec_sync/test_released_schemas.py` runs the same check in the tests job |
| `gen_vocabulary.py [--check]` | generates `src/materica/schema/0.1/vocabulary/*.json`, each with its `$id`, from the specification's tables and the token lists in its cells and sentences: reasons with the steps that give them, fields, conditions, specimen facts, acceptance kinds, the forms' tokens and the element symbols, statistics and uncertainty tokens, provenance tokens and result labels; the pattern of an identifier a fact's row writes (`"UBERON:<digits>"`); and the bindings the writer schema applies, each section's field names and each field's forms, bases, unit and label, the fields an overlay may replace, and each numeric condition's unit; a list of tokens is read in full, and a cell or list it cannot read, a name listed twice in one table, or a row a binding cannot state, stops it | with `--check`, in the generated-files job, when a change touches code |
| `gen_reader_schema.py [--check]` | generates `schema/0.1/record.reader.json` from the writer schema, opened where `record_format.md` section 1 item 2 says a reader is open, with the shapes of a value field and a section's `specimen` in `$defs`, as step 8 checks them: without the members marked `x-materica-write-only`, a member marked write-only `unless` a condition checked under that condition alone, and without the vocabulary's bindings, which bind a field to its row and which a read checks in its own steps; it refuses a writer schema it cannot open faithfully, such as anything it opens under `if` or `not`, there or through a `$ref`, or a keyword it does not know | as above |
| `gen_shapes.py [--check]` | generates `src/materica/shapes.py` and `shapes.pyi`, the JSON shapes as TypedDicts, from the writer schema, `case.json` and the read request and result, with datamodel-code-generator and ruff (pinned in the dev group), working in a temporary copy of the schemas in which every `integer` is a `number`, since the reader gives every number as a double, and the vocabulary's bindings are left out, since a TypedDict cannot narrow a member by the name it sits under; runs on Python 3.11 to 3.14, since the generator does not run on 3.15 | as above |
| `repeat_runs.py request \| seeds \| derandomized \| record SEED STATUS REPORT \| summary DIRECTORY` | the repeat workflow's checks and sums (`.github/workflows/repeat.yml`). `request` checks a dispatch's inputs, read from the environment, and writes them as the step's outputs: it refuses a node that is not a file or directory under `tests/` (by a path of plain parts, never `..`, and inside `tests/` once resolved), a profile or a Python not listed, a count or a first seed out of its bounds or not in plain digits, a character other than printable ASCII, and any extra argument but `--shard` and `--property-controls`, each once, giving every reason; `seeds` lists one job's seeds, no two runs of a request sharing one; `derandomized` reads the node ids pytest collected and warns, never refuses, where any lies in a module whose searches are derandomized (one `PROPERTY_CONTROLS` selects, or whose code sets `derandomize=True` or runs `MUTANT_SEARCH`), whose every repeat draws the same examples; `record` writes one run's record, a line of JSON, from pytest's exit status and JUnit report, with each failing example Hypothesis reported; `summary` sums every job's records in the step summary (the runs, the failures with their seeds and examples, and the failure rate with its one-sided 95 % upper bound) and fails where a run failed or did not finish, a seed has no record or two, a job of runs did not succeed, or the run's attempt (`ATTEMPT`) is not its first; of a seed's two records, as from a job run again, it counts the one that did not pass. Standard library only | never on a push or a pull request: in the repeat workflow, which runs only when dispatched by hand (`tests/README.md`, "Repeat runs on CI") |
| `pre_review.py [BASE] [--list] [--stage fast\|tests\|properties] [--workers N] [--keep-going] [--key-file KEY]` | the builder's check before asking for review (CONTRIBUTING, "Before asking for review"): finds the files changed from the merge base of `BASE` (`origin/main`) and `HEAD` to the working tree, with the untracked, and runs the checks that apply, printing each with the paths that selected it. Every change: the sign-off and confidential scans, every generator's `--check` on Python 3.11 in an environment of its own, and `freeze_schema.py --check`; a change to code, as CI's gate reads it: ruff, `ruff format --check`, mypy and pyright, then the static job's wheel steps (`uv build`, `check_wheel.py` and the consumer snippet's mypy and pyright against the installed wheel, in a temporary directory; `--wheel-check` runs them alone); a changed Python file: the test files that import it, directly or through others, those of `tests/property` as their whole shard at the `ci` profile, and the few tests that read the whole tree instead of importing it (`TREE_READERS`); a changed specification, schema, conformance, spec-sync table, workflow or build file: the tests that hold it or open it (`DATA_RULES`), and the shards of the modules that read it. A change it cannot map to a test (a Python file no test imports, a file under `tests/` in no group of tests, a conftest of a directory that is none) selects the whole of `tests/unit` and says why. A stage that fails stops the run before the next unless `--keep-going`. It ends with reminders for what no check decides: code beside a CHANGELOG that was not, and each count the branch's CHANGELOG lines and commit messages state, to recount. Every `uv run` it plans is `--locked` and `uv lock --check` comes first, so a lock file out of date is refused, never rewritten. A name in a diff is printed with its control characters escaped and a command quoted so that it pastes back as the same arguments; a file that is no regular file is not opened, and one that is not UTF-8 is named and sends its change to the whole of `tests/unit`. It runs what applies, never all that CI runs (not the site job, the fuzz job or the wheel check's two controls), and replaces none of it. Standard library only | never: a builder's tool |
| `mutant_runs.py request \| run DIRECTORY \| imports [PATH ...] \| table DIRECTORY OUTPUT` | the mutant workflow's checks, runs and table (`.github/workflows/mutants.yml`). `request` checks a dispatch's inputs, read from the environment, and every patch they name, and writes them as the step's outputs, the matrix of jobs among them (the baseline, `""`, and each mutant): a patch must be `mutants/<name>.patch`, a regular file committed at the dispatched commit, named by 1 to 64 letters, digits, `_` and `-`, at most 1 MiB of UTF-8 text with no control character but tab and line feed, that git reads as a patch in its own format, each file's `diff --git`, `---` and `+++` lines naming its one path, with no binary data, rename, copy, link or submodule, touching only plain paths inside the checkout, none inside `.git`, under `.github/` or `mutants/`, none git ignores, nor the runner, `pyproject.toml`, `uv.lock`, `uv.toml`, `.python-version` or `.python-versions`; a selection of paths or nodes under `tests/`, a profile and a Python listed, a seed in plain digits or one drawn at random, and `--shard` and `--property-controls` alone; it gives every reason. `run` checks one mutant's patch again, applies it, runs `imports` in the project's environment, collects the selection and runs it until the first failure, each through `uv run --no-sync --frozen`, under `timeout --foreground --signal=INT` three minutes before the job's timeout, counted from the job's start (`JOB_STARTED`), and writes the facts to `record.json`, never a verdict; `verdict` alone makes one: broken where the patch did not apply or the code did not import or collect, in one process or under pytest-xdist (what the report names beside the collected tests, `uncollected`), whatever else the record holds, survived, killed (with the collected test that failed first) or undecided. `imports` compiles each Python file it is given and imports every module of the package from the checkout. `table` writes one row for the baseline and each mutant to the step summary and to `table.md` and `table.json`, with the paths its patch touches, marking a kill by a patch that edits the tests or pytest's settings, and the line that replays a row with the dispatch's selection and seed, and fails unless the baseline passed and every mutant was killed, each with one record, the mutants' jobs succeeded and the run is on its first attempt. Standard library only, and self-contained, since a mutant's job runs it from a copy outside the checkout | never on a push or a pull request: in the mutant workflow, which runs only when dispatched by hand (`tests/README.md`, "Mutant tables on CI") |
| `report_test_durations.py <report> [--title TITLE]` | summarises a JUnit report pytest wrote (`--junitxml`; pytest-xdist's controller writes one for all its workers) in Markdown, appended to the step summary: the tests in each band of wall time, the 30 slowest tests and the 15 slowest files, and the total, each with the CPU time `tests/conftest.py` records beside the wall time; the tests an interrupt stopped before the job's timeout, which pytest writes with a time alone, are counted and left out; no duration fails it, and a report missing, unreadable, written without each test's file, or with no test that ran to its end exits 2 | after each pytest job's tests, in the test matrix and in each Hypothesis shard, passed, failed or interrupted |
| `schema_index.py <directory>` | writes an `index.html` into a published schema tree and each directory under it, linking what each holds, with every JSON file's `$id` and its schema's title and description, and a "draft until" note on the page of each version that `tests/spec_sync/released_schemas.json` does not list; refuses a tree that already holds an `index.html`, a directory under the root that is no version (`<MAJOR>.<MINOR>`, or `<MAJOR>.<MINOR>-dev` for the next line's development, renamed `<MAJOR>.<MINOR>` at its release, which the freeze then records), a line held as both `-dev` and released, and an unreadable manifest | in the Pages workflow, on its staged copy of `src/materica/schema/`, at every deployment |

A generator writes its files; with `--check` it writes nothing and fails where a file on disk differs from what
its source gives, so a hand edit to a generated file, or a source edited without regenerating, fails CI
(CONTRIBUTING, "Changing the schema"). Each script has tests in `tests/unit/` that show it failing on what it
must refuse.

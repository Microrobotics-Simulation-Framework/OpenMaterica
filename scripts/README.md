# Scripts

Development and CI tools; nothing in the package imports them. All but `gen_shapes.py` use Python's standard
library only, so the sign-off check runs before any dependency is installed.

| Script | What it does | When CI runs it |
|---|---|---|
| `check_confidential.py [--key-file KEY] [--messages RANGE]` | checks that no tracked file, and no message of a commit in `RANGE`, names one of the maintainer's private projects or carries a private path (CONTRIBUTING, "Confidentiality"); the names by their HMAC-SHA256 in `confidential_digests.txt`, under a key from `CONFIDENTIAL_SCAN_KEY` or `--key-file`, and the paths without a key. A finding gives a term's first letter and length, never the term. `--digest` writes the digest file from terms on standard input | on every pull request and push, in the first job, whatever the change touches, with the messages the event brings; without the secret, the paths only, with a warning |
| `check_signoff.py <base> <head>` | checks that every commit in `base..head` carries a DCO `Signed-off-by` from its author (CONTRIBUTING constraint 1); the design commits made before the first code commit are exempt, by ancestry of one pinned commit | on every pull request, in the first job, whatever the change touches |
| `check_wheel.py <wheel>` | checks that the built wheel holds `py.typed`, every file under `data/` and `schema/` byte for byte and no other there, the licence as an SPDX expression with its file (PEP 639), no run-time dependency, and nothing outside the package | in the static job, after `uv build`, when a change touches code |
| `freeze_schema.py <MAJOR.MINOR> \| --check` | at a release, adds the schema version to `tests/spec_sync/released_schemas.json`, with every file under `src/materica/schema/<version>/` and the SHA-256 of its bytes; refuses a version whose `$id`s are not their paths, and never rewrites one already there. `--check` writes nothing and fails where a released version's file was added, removed or changed, an `$id` is not its path, or its directory is gone (CONTRIBUTING, "Release gate") | not as a step of its own: `tests/spec_sync/test_released_schemas.py` runs the same check in the tests job |
| `gen_vocabulary.py [--check]` | generates `src/materica/schema/0.1/vocabulary/*.json`, each with its `$id`, from the specification's tables and the token lists in its cells and sentences: reasons with the steps that give them, fields, conditions, specimen facts, acceptance kinds, the forms' tokens and the element symbols, statistics and uncertainty tokens, provenance tokens and result labels; the pattern of an identifier a fact's row writes (`"UBERON:<digits>"`); and the bindings the writer schema applies, each section's field names and each field's forms, bases, unit and label, the fields an overlay may replace, and each numeric condition's unit; a list of tokens is read in full, and a cell or list it cannot read, a name listed twice in one table, or a row a binding cannot state, stops it | with `--check`, in the generated-files job, when a change touches code |
| `gen_reader_schema.py [--check]` | generates `schema/0.1/record.reader.json` from the writer schema, opened where `record_format.md` section 1 item 2 says a reader is open, with the shapes of a value field and a section's `specimen` in `$defs`, as step 8 checks them: without the members marked `x-materica-write-only`, a member marked write-only `unless` a condition checked under that condition alone, and without the vocabulary's bindings, which bind a field to its row and which a read checks in its own steps; it refuses a writer schema it cannot open faithfully, such as anything it opens under `if` or `not`, there or through a `$ref`, or a keyword it does not know | as above |
| `gen_shapes.py [--check]` | generates `src/materica/shapes.py` and `shapes.pyi`, the JSON shapes as TypedDicts, from the writer schema, `case.json` and the read request and result, with datamodel-code-generator and ruff (pinned in the dev group), working in a temporary copy of the schemas in which every `integer` is a `number`, since the reader gives every number as a double, and the vocabulary's bindings are left out, since a TypedDict cannot narrow a member by the name it sits under; runs on Python 3.11 to 3.14, since the generator does not run on 3.15 | as above |
| `report_test_durations.py <report> [--title TITLE]` | summarises a JUnit report pytest wrote (`--junitxml`; pytest-xdist's controller writes one for all its workers) in Markdown, appended to the step summary: the tests in each band of wall time, the 30 slowest tests and the 15 slowest files, and the total, each with the CPU time `tests/conftest.py` records beside the wall time; the tests an interrupt stopped before the job's timeout, which pytest writes with a time alone, are counted and left out; no duration fails it, and a report missing, unreadable, written without each test's file, or with no test that ran to its end exits 2 | after each pytest job's tests, in the test matrix and in each Hypothesis shard, passed, failed or interrupted |
| `schema_index.py <directory>` | writes an `index.html` into a published schema tree and each directory under it, linking what each holds, with every JSON file's `$id` and its schema's title and description; refuses a tree that already holds an `index.html` | in the Pages workflow, on its staged copy of `src/materica/schema/`, at every deployment |

A generator writes its files; with `--check` it writes nothing and fails where a file on disk differs from what
its source gives, so a hand edit to a generated file, or a source edited without regenerating, fails CI
(CONTRIBUTING, "Changing the schema"). Each script has tests in `tests/unit/` that show it failing on what it
must refuse.
